ROOFTOP SOLAR CALCULATOR - MAC SETUP

One-time setup
1. You need Python 3.10 or newer. If you don't have it, install it from
   https://www.python.org/downloads/ (download the macOS installer and run it).
2. Double-click "Install.command". It takes a minute or two and ends with
   "passed" and "Installed."

   If macOS says the file can't be opened because it's from an unidentified
   developer: click Done, open System Settings > Privacy & Security, scroll
   down and click "Open Anyway" next to Install.command. Do the same the first
   time you open "Size Buildings.command".

Sizing a list of properties (no drawing needed)
1. Make a spreadsheet with one row per property and save it as .csv
   (Excel: File > Save As > CSV; Numbers: File > Export To > CSV).
   Columns (header names are matched loosely):
     Name                    optional; used to label results
     Address                 full address, OR separate Street/City/State/Zip
                             columns, OR Latitude and Longitude columns
     Property Type           optional: Multifamily or Commercial
     Group                   optional: for a property with several buildings,
                             use one row per building (its own address or
                             Latitude/Longitude) and give them the same Group.
                             Totals per Group go to <name>_results_properties.csv
2. Double-click "Size Buildings.command", drag the .csv in, press Return.
   The first run takes about a minute extra to build a map index.
3. Results appear next to your file:
     <name>_results.csv            one row per property
     <name>_results_buildings.csv  one row per building found
     <name>_layouts.kml            roof outlines (yellow) and panels; open in
                                   Google Earth to check the right roof was used
   Two MaxFit numbers per property: dc_kw (standard racking, panels go
   around rooftop equipment) and maxfit_raised_racking_kw (raised racking
   also spans equipment gaps up to ~20 ft wide on flat roofs, including
   equipment against a roof edge; an estimate, drawn orange in the
   _layouts.kml). rooftop_kw
   and carport_kw split dc_kw.
   Panels are kept 3 ft clear of rooftop equipment (condensers, vents) found
   in Google's roof height map: one extra Google lookup per flat roof,
   cached after the first run. equipment_clearance_kw_not_counted shows what
   that removed; maxfit_raised_racking_kw adds it back over the equipment.
   In the _layouts.kml, each property has its own folder (double-click it in
   Google Earth's Places panel to fly there): yellow roof outlines, blue
   panels, red detected equipment, orange raised-racking-only areas.
   Satellite snapshots: when asked, type part of the site names (e.g.
   Garrison;Alexander). A PNG per site with the layout drawn on Google's aerial
   photo goes into a _snapshots folder; one billed Google lookup per site.
   Pitched roofs: panels are kept 36 in from roof-plane edges (ridges, hips,
   eaves); add --pitched-setback-in 18 where the AHJ allows 18 in. Detached
   garages and carports count only if unshaded and 15 kW or more fits.
   Look by hand at rows where manual_review is TRUE: the satellite imagery
   is old, or shows much less roof than the building outline (often a
   building finished after the photo). The window shows how many there are.
   The "reasons" column has notes on every row, e.g. the address matched a
   building 30 m away, or two buildings were equally close.

To try it now, drag in examples/sample_sites.csv (six real Los Angeles
buildings picked from the map data; not your properties).

How roofs are found: addresses are located with the free US Census geocoder,
then matched to building outlines from Overture Maps (free, open data that
combines OpenStreetMap, Microsoft and Google building footprints).

Drawing roofs yourself in Google Earth (optional, for single sites)
- Draw each roof outline as a polygon and save as .kml/.kmz, then drag that
  file in instead of a .csv. Polygons inside a roof named HVAC, Vent,
  Skylight, Hatch, Standpipe or Smoke vent are treated as obstructions;
  "plane 6/12 S" marks a pitched roof face. See README.md for details.

Checking accuracy against your own designs
- Double-click "Accuracy Test.command" and drag in a truth file: either
  truth_drive.json from accuracy_test.zip, or a CSV with columns
  name, address, latitude, longitude, true_kw, module_w (one row per design).
- It prints each site's result with and without Google roof data and writes
  <name>_accuracy.csv plus a .kml you can open in Google Earth to check that
  the right buildings were matched.

Optional
- Regrid parcels (finds every building on a multi-building property): save
  your Regrid API token as ~/.rooftop-solar/regrid_token. It is used
  automatically. The free trial token only covers 7 sample counties
  (e.g. Dallas County, TX); examples/regrid_trial_dallas.csv has three real
  Dallas apartment buildings for checking that it works.
- Calibration: put calibration.json in the same folder as your buildings file
  and it is applied automatically.
- Google Solar cross-check: save your API key as a plain text file at
  ~/.rooftop-solar/google_api_key (Google bills per new building looked up).

After an update: replace this folder with the new version and double-click
Install.command again.

Full documentation: README.md

Installed systems from public permit data (optional):
   Double-click 'Pull Permits.command'. It downloads rooftop solar permits of
   30 kW and up from city open data (SF, LA, Austin, Seattle, Chicago, NYC;
   free) into Downloads/permits_truth.csv, at most 40 sites per city. Drag
   that file into 'Accuracy Test.command'. Installed systems are minimums:
   the test reports what share of the tool's MaxFit typically gets built.
